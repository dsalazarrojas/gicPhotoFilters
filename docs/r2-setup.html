Optional R2 storage

Turn direct mode into shareable result mode

This repo now works without R2 by returning transformed images directly from /api/transform. If you also want 24-hour result URLs, stored uploads, and richer sharing, bind an R2 bucket and switch STORAGE_MODE to r2.

1. Create two R2 buckets

In Cloudflare, create gic-photo-filters-temp and an optional preview bucket for local development. Add a 24-hour lifecycle rule so generated images clean themselves up.

2. Bind PHOTO_BUCKET

Uncomment the [[r2_buckets]] section in wrangler.toml, or add the same binding in the Cloudflare Pages dashboard. The binding name must stay PHOTO_BUCKET.

3. Switch storage mode

Set STORAGE_MODE="r2" for deployments that should keep results for 24 hours. Leave it at direct if you want the lighter no-billing-required setup.

Mode comparison

Choose the deployment model that fits your launch

Both modes are supported by the repo now, so you can start with the easiest path and upgrade later.

Direct mode

Best for quick demos and lower-friction deployments. Results come back once in the transform response, so visitors should download them immediately.

R2 mode

Best for public launches that want shareable URLs, upload-backed workflows, and 24-hour temporary storage served through /api/image/:key.

Verification

Check the deployment health

After deployment, visit /api/health. It now reports storage.mode, storage.r2Available, and this setup guide URL when R2 is still missing.

  • Healthy direct mode: storage.mode = "direct", shareableResults = false.
  • Healthy R2 mode: storage.mode = "r2", r2Available = true.
  • Needs attention: storage.mode = "r2" with r2Available = false.
